⸻

8. UI界面设计规范

8.1 UI总原则

本项目 UI 设计必须服务于以下三个目标：

1. 保证战斗信息清晰可读
2. 保持 90 年代日式奇幻动画的视觉统一性
3. 不抢角色与卡面的主视觉

UI 在本项目中不应被设计为“独立炫技层”，而应被视为附着在战斗画面之上的 功能性前景系统。
整体应像传统奇幻作品中的界面板、金属铭牌、羊皮纸信息框、魔法纹章，而不是现代手游浮空半透明 HUD。

⸻

8.2 UI风格定位

视觉关键词

* 老派奇幻
* 日式90年代RPG/动画感
* 金属边框
* 宝石嵌角
* 深色底板
* 纹章式分区
* 清晰层级
* 装饰克制
* 可读优先

风格来源说明

UI 的风格应与角色、背景共享同一世界观逻辑：

* 角色是 90 年代赛璐璐动画角色层
* 背景是 手绘背景板
* UI 是 覆盖在前景的奇幻系统层

战斗视角的信息组织，也应延续你指定的“我方背面、敌方正面”逻辑；早期宝可梦素材中长期存在大量 trainer back sprites 的资源组织方式，这种“玩家侧背面、对手侧正面”的信息分工，本身就非常适合你的卡牌对峙界面。 

⸻

8.3 UI禁止项

以下方向禁止采用：

* 现代二游玻璃拟态
* 大面积半透明磨砂浮层
* 高亮霓虹描边
* 科幻蓝紫电子屏风格
* 赛博、机械、芯片感图形
* 过多漂浮信息条
* 技能按钮像 MOBA / 手游大厅按钮
* 大量粒子特效覆盖卡面与角色
* 复杂镜面金属质感
* 厚涂写实材质按钮

⸻

8.4 UI整体配色规范

UI 推荐采用以下主色体系，与角色、卡牌稀有度系统协调：

基础主色

* 深蓝
* 暗金
* 墨绿
* 紫黑
* 棕褐
* 象牙白

使用原则

* 深色做底
* 暗金做结构边框
* 高亮色只用于强调
* 同屏高亮不超过 2 个主色点

稀有度/属性色建议

* 战士 / 物理：深蓝、铁灰、暗金
* 火焰 / 爆裂：深红、铜金、橙红
* 法术 / 神圣：象牙白、金色、淡青白
* 暗影 / 诅咒：紫黑、暗紫、深洋红
* 森林 / 弓箭 /自然：墨绿、青绿、金褐

⸻

8.5 字体与文字系统

字体气质要求

字体需表现出：

* 古典奇幻感
* 读数清楚
* 小字号依然可读
* 不要未来科技感
* 不要可爱Q萌感

标题字建议

* 带一点碑文、铭文、古典装饰感
* 适合卡名、章节名、弹窗标题

正文字建议

* 清楚、规整、便于战斗中快速阅读
* 不使用过度装饰体
* 不使用极细字重

文本规则

* 战斗中数值、卡费、攻击、防御、状态名称必须优先可读
* 描述文本允许有轻微装饰，但不能影响扫描速度
* 避免一切“为了复古而牺牲读性”的做法

⸻

8.6 主界面设计规范

8.6.1 主界面目标

主界面负责传达：

* 世界观气质
* 当前章节/区域
* 玩家入口功能
* 卡组与战斗入口

布局建议

* 中央主视觉：角色组或场景主图
* 左/右侧或底部：功能按钮分区
* 顶部：资源栏
* 下方：主要入口（开始战斗、卡组、背包、图鉴、设置）

主界面视觉要求

* 像传统奇幻冒险菜单，而不是现代直播感首页
* 按钮像“铭牌”“卷轴按钮”“金属镶边按钮”
* 背景可用城堡、森林、遗迹、地图板等手绘背景

⸻

8.7 战斗界面设计规范

8.7.1 战斗界面核心原则

战斗界面必须明确区分以下层级：

1. 背景板
2. 敌方战斗区域
3. 我方战斗区域
4. 卡牌操作区
5. 状态/UI信息层
6. 临时特效层

任何时候都不能让 4、5、6 层压倒角色主体。

⸻

8.7.2 战斗界面布局建议

敌方区域

* 位于右上
* 显示敌方角色正面/3_4正面立绘
* 敌方 HP、状态、护盾、异常状态显示在其附近
* 若有敌方手牌/意图，可用较小图标提示，不要抢主画面

我方区域

* 位于左下
* 显示我方角色背面/背侧立绘
* 我方 HP、能量、护盾、状态显示在角色附近
* 玩家可操作区域需与角色画面分离

中央区域

* 用于攻击演出、卡牌结算、法术命中、召唤物表现
* 不宜长期堆放固定 UI 元素

底部区域

* 手牌区
* 回合按钮
* 能量/费用显示
* 主要交互按钮

⸻

8.7.3 战斗信息优先级

战斗时同屏优先级建议如下：

第一优先级

* 角色位置
* 当前攻击对象
* 血量
* 当前可用卡牌
* 回合状态

第二优先级

* 护盾
* BUFF / DEBUFF
* 能量/费用
* 抽牌/弃牌提示

第三优先级

* 战斗日志
* 风味文本
* 次级动画修饰
* 环境特效

⸻

8.7.4 战斗按钮设计

按钮风格建议：

* 深色底板 + 暗金描边
* 带少量奇幻纹章
* 按下时有明确亮度变化
* Hover/选中状态可以轻微发光，但必须克制

主要按钮建议：

* 攻击 / 出牌
* 结束回合
* 查看详情
* 取消
* 自动 / 倍速（若有）

禁止项

* 荧光描边
* 大面积蓝白高光
* 现代玻璃水晶按钮
* 太多按钮同时闪烁

⸻

8.8 卡牌界面设计规范

8.8.1 卡牌总原则

卡牌是本项目最核心的交互资产之一。
其设计必须兼顾：

* 收藏感
* 可读性
* 世界观一致性
* 战斗中的快速识别

卡牌不应做成现代手游“华丽爆炸边框”，而应更接近 老派奇幻道具牌/魔法卷轴/英雄铭牌 的感觉。

⸻

8.8.2 卡牌版式建议

每张卡牌建议包含以下区域：

1. 左上：费用
2. 顶部：卡名栏
3. 中央：插画区域
4. 下方：效果描述区
5. 底部：标签/属性/职业
6. 四角或边框：稀有度装饰

版式要求

* 插画区占比高，保证收藏价值
* 文本区规整，不能压缩到无法阅读
* 卡费必须一眼识别
* 边框复杂度不能过高，防止抢插画

⸻

8.8.3 卡框设计要求

卡框基调

* 金属 + 宝石 + 雕纹
* 奇幻神殿、古代铭文、骑士团徽章感
* 允许少量发光魔法纹，但不可现代化

按卡牌类型区分框体

* 角色卡：厚重、徽章感强
* 法术卡：纹样更流动、边框可略轻
* 装备卡：金属质感更明显
* 陷阱/诅咒卡：边框可更尖锐、更暗

稀有度表现建议

* 普通：铁灰 / 铜色
* 稀有：深蓝 / 银蓝
* 史诗：紫金 / 深紫
* 传说：暗金 / 红金 / 白金

⸻

8.9 状态栏与数值条设计规范

血条

* 清楚、厚度适中
* 有边框包裹
* 颜色区分健康/危险状态
* 不宜做得太细

能量条 / 法力条

* 独立于 HP 条
* 可使用更冷的色相
* 需和费用数字统一视觉

状态图标

* 尺寸统一
* 图标语义明确
* 每个异常状态要能通过轮廓快速识别
* 不使用现代扁平化线性 icon 套件

数值显示

* 暴击、伤害、治疗数字可短暂放大
* 动效不宜太弹跳卡通
* 更适合“干脆出现—停留—淡出”的老派节奏

⸻

8.10 弹窗与面板设计规范

弹窗类型包括：

* 卡牌详情
* 角色详情
* 背包
* 设置
* 获得新卡
* 升级/强化
* 任务结算

面板风格

* 像古代卷轴、石板、铭牌、木框或金属嵌板
* 带装饰边，但不能过厚
* 面板层次要明显高于背景，低于关键角色演出

动画建议

* 缓慢展开
* 淡入 + 轻微位移
* 不做现代大幅缩放跳脸动画

⸻

8.11 图标系统设计规范

图标系统建议分为：

* 属性图标
* 状态图标
* 稀有度图标
* 菜单图标
* 职业图标
* 资源图标

图标统一要求

* 轮廓明确
* 风格统一
* 带一点手绘雕刻感
* 不走极简扁平路线
* 不走过度写实路线

推荐视觉方向

* 徽章式
* 浮雕式
* 魔法印记式
* 古典纹章式

⸻

8.12 动效与转场规范

UI 动效必须服从“老派奇幻、克制、清楚”的原则。

推荐动效

* 淡入淡出
* 轻微平移
* 卡牌翻开
* 金属铭牌出现
* 魔法纹样短暂闪现
* 选中时轻微亮边

不推荐动效

* 高频闪烁
* 大幅跳动
* 粒子雨覆盖全屏
* 科技扫描线
* 未来电子噪波
* 直播礼物式夸张特效

⸻

8.13 分辨率与适配建议

UI 设计需从一开始考虑不同平台和比例下的安全区。

建议规范

* 先按主目标分辨率设计基准稿
* 预留左右边距和底部操作安全区
* 顶部资源栏避免贴边
* 战斗中卡牌区与敌我角色区不要互相侵占

特别要求

* 小屏下优先保留：
    * 卡费
    * HP
    * 回合状态
    * 可操作卡牌
* 次级信息可折叠或二级展开

⸻

8.14 UI与美术协同要求

UI 设计必须和角色、场景、卡面团队同步，不允许独立脱节。

需要统一的部分

* 颜色母体
* 线条粗细倾向
* 装饰元素语言
* 金属与纹章样式
* 魔法特效语言
* 世界观材质表达

统一目标

做到用户在同一画面中看到：

* 角色
* 背景
* 卡框
* 按钮
* 状态栏

时，会自然认为它们属于 同一个90年代奇幻动画世界，而不是“角色是复古动画，UI 却是现代手游”。

⸻

8.15 UI验收标准

UI 通过验收需满足：

* 与角色和背景风格统一
* 功能分区明确
* 战斗中信息一眼可读
* 不抢卡面插画和角色立绘
* 具备老派奇幻感
* 没有现代二游玻璃与霓虹感
* 卡牌与按钮在小尺寸下仍清晰
* 同屏层级关系稳定
* 能直接服务“我方背面、敌方正面”的对峙式战斗结构

⸻

8.16 UI一句话定义

本项目 UI 是建立在 90 年代日式赛璐璐奇幻动画审美上的“功能性前景系统”，以老派奇幻铭牌、卷轴、金属边框和纹章语言为主，服务于卡牌对峙战斗的信息清晰度，而不是现代手游式的高光炫技界面。 这一界面逻辑需要和你选定的赛璐璐角色层、手绘背景板层，以及“玩家侧背面 / 敌人侧正面”的对战信息组织保持一致。
